## 2026-09-04：实例「高级」页升级为启动配置（启动参数 / 内存限制 / 进程优先级）

- **功能**：每个实例的「高级」页即一份启动 Profile（按实例独立，完全替代原先单个启动参数字符串框），承载三项：自定义启动参数、内存限制、进程优先级。启动游戏时按该配置应用。

- **内存限制**：KSP 是 64 位 Unity 游戏，没有 Java 式 `-Xmx`，故采用系统级进程内存上限——Windows 用 **Job Object**（`JobMemoryLimit`）+ `AssignProcessToJobObject` 绑定游戏进程（`processopt::openMemoryJob`，进程退出/析构时 `closeMemoryJob` 释放）；Linux/macOS 用 `QProcess::setChildProcessModifier` → `setrlimit(RLIMIT_AS)`。单位为 MB，`0` 表示不限制（界面上限 64GB）。

- **进程优先级**：下拉「高 / 低」。高=启动前结束 Edge/Chrome/Firefox 浏览器进程（Windows `taskkill /IM`、POSIX `pkill`）+ 启动后把游戏进程设为高优先级（Windows `SetPriorityClass(HIGH_PRIORITY_CLASS)`、POSIX `setpriority(-5)`）；低=不做任何处理。结束浏览器的说明仅在点「确认保存」（`onSaveLaunchArgsClicked`）时一次性提示，启动时不重复弹窗。

- **持久化**：`KSPInstance` 新增 `launchMemoryMB`（默认 0）与 `launchHighPriority`（默认 false），随实例一并写入 `HKSPL.json`；`ConfigManager` 新增 `instanceLaunchMemoryMB/setInstanceLaunchMemoryMB/instanceLaunchHighPriority/setInstanceLaunchHighPriority`。

- **实现**：新增跨平台进程钩子 `src/processopt.h/.cpp`（`browserKillCommands` 纯函数生成浏览器结束命令、`killBrowsers`、`setProcessHighPriority`、Windows `openMemoryJob/closeMemoryJob`、POSIX `setChildMemoryLimit`）；`InstanceManager::launchGame` 扩展签名 `(exePath, args, memoryLimitMB, highPriority)` 并应用优先级与内存限制（`src/instancemanager.h/.cpp`）；UI 升级 `instancedetailpage_settings.cpp` 高级页（参数框 + 内存 QSpinBox + 优先级下拉），`onSaveLaunchArgsClicked` 一次性保存三项；`mainwindow.cpp` `onLaunchClicked` 启动时按配置透传（结束浏览器 + 提升优先级 + 内存 Job）。

## 2026-08-29 v1.1.2：整合包导出（打包 GameData 为 ZIP）做内存与小文件优化

- **内存**（`instancemanager_modpack.cpp`）：原实现 `collectExportFiles` 一次性把全部条目（`ExportFileEntry`）收集成 `QList` 并排序，巨型包这份清单全部驻留内存。改为 `walkExportFiles` 回调式遍历、两遍执行——第一遍仅统计总字节并确认非空，第二遍逐条写入，导出过程不再保存任何文件清单；相应移除按路径排序（换取不驻留列表，磁盘局部性让位于内存）。

- **小文件**：`≤1MB` 小文件（KSP 绝大多数模组文件）读入受限缓冲后 `mz_zip_writer_add_mem` 一次写入，免去逐块回调 + 多次 seek 开销；`>1MB` 大文件仍走 `mz_zip_writer_add_read_buf_callback` 流式读取（单文件内存固定）。目录条目沿用 `ensureExportDirs` 去重缓存。

- **写缓冲合并写盘**：miniz 逐条写本地头/文件名/extra/压缩输出等小块时，若每块直接落盘会触发海量 `seek+write` 系统调用（打包 I/O 瓶颈、CPU 吃不满）。新增 `BufferedFileWriter` 接在 `mz_zip_writer` 的 `m_pWrite` 上，把顺序小块攒满 1MB 再一次性落盘，非顺序偏移兜底先刷后直写；归档 finalize 后统一 `flush` 剩余缓冲再关文件。写后端仍为 `QFile`，兼容 Unicode 路径。

## 2026-08-29：整合包导入改用流式解压（修复整包载入内存/卡 UI，并优化巨型包内存）

- **修复整包载入内存**（`modpackio.cpp`）：旧的 `openZipFromFile` 用 `f.readAll()` 整包读入内存（绕开 miniz `init_file` 的 ANSI 路径问题），且导入前的前缀探测在主线程同步执行会卡 UI、探测完即释放造成重复读入。现改用 `mz_zip_reader_init_cfile` + 宽字符 `_wfopen`（POSIX 用 UTF-8 `fopen`）按需 fseek/fread 懒读取，全程不整包进内存；`OpenedZip::close()` 同时 `mz_zip_reader_end` 并 `fclose`（CFILE 模式下 miniz 不负责关文件）。

- **巨型包内存优化**：单文件解压从 `extract_to_heap`（整个文件进堆）改为 `extract_iter_*` 流式迭代器（固定约 96KB 缓冲，保留 CRC 校验）；去掉保存全部条目索引/路径的 QVector（改两遍遍历：第一遍只统计 + 全量防 Zip Slip 校验，通过后才清空 GameData，第二遍再逐条解压）；`init_cfile` 传 `DO_NOT_SORT_CENTRAL_DIRECTORY` 省中央目录排序数组。进度改为每解压 1MB 平滑上报。

- **零散小文件解压优化**（KSP 模组以大量小文件为主）：按大小分流，`≤1MB` 小文件用 `extract_to_heap` 一次性解压 + 单次写盘，省去每个小文件创建/释放流式迭代器（\~100KB）的开销；`>1MB` 大文件才走流式迭代器保证内存固定。父目录用 QSet 缓存，每个目录只 `mkpath` 一次，避免几万个小文件重复目录系统调用。

## 2026-08-28（固定）：修复安装模组时下载进度条不走

- **问题**：安装模组时文件实际在下载，但进度条一直停在 0%、状态文字停留在「准备下载」，直至结束。

- **根因**：`CKan::ensureInstaller()` 惰性创建的 `ModuleInstaller` 归属线程是调用它的 worker 线程（下载/安装阶段均在 `QtConcurrent::run` 内），其 `byteProgress` 信号由线程池线程发出，AutoConnection 把排队槽投递到接收对象（即安装器自身）的归属线程——该 worker 线程在 `waitForFinished()` 阻塞且无事件循环，排队回调在整个下载期间无法被派发，`m_byteProgress` 从未触发 → UI 收不到进度。安装阶段 `installProgress` 因走同线程 Direct 调用不受影响。

- **修复**：创建安装器后显式 `moveToThread(QCoreApplication::instance()->thread())` 将其归属到主线程，使进度回调正确回落到带事件循环的 UI 线程（普通方法直接调用不受线程归属影响，`downloadModules`/`installFromCache`/`cancel` 仍安全）。

- **验证**：`HelloKSPLauncher.exe` 构建成功；`ctest` 两个套件（test\_libckan / test\_launcher）全部通过。
