## 2026-08-28（固定）：修复安装模组时下载进度条不走

- **问题**：安装模组时文件实际在下载，但进度条一直停在 0%、状态文字停留在「准备下载」，直至结束。
- **根因**：`CKan::ensureInstaller()` 惰性创建的 `ModuleInstaller` 归属线程是调用它的 worker 线程（下载/安装阶段均在 `QtConcurrent::run` 内），其 `byteProgress` 信号由线程池线程发出，AutoConnection 把排队槽投递到接收对象（即安装器自身）的归属线程——该 worker 线程在 `waitForFinished()` 阻塞且无事件循环，排队回调在整个下载期间无法被派发，`m_byteProgress` 从未触发 → UI 收不到进度。安装阶段 `installProgress` 因走同线程 Direct 调用不受影响。
- **修复**：创建安装器后显式 `moveToThread(QCoreApplication::instance()->thread())` 将其归属到主线程，使进度回调正确回落到带事件循环的 UI 线程（普通方法直接调用不受线程归属影响，`downloadModules`/`installFromCache`/`cancel` 仍安全）。
- **验证**：`HelloKSPLauncher.exe` 构建成功；`ctest` 两个套件（test_libckan / test_launcher）全部通过。

## 2026-08-16：修复模组列表显示旧版本而非最新版本

- **问题**：同一模组（如 Kerbal Konstructs）在启动器模组列表中显示为 `0.5.1b`，而官方 CKAN 显示并安装 `v1.12.2.0`。
- **根因**：`CKan::search()` 用 `versions.first()` 取每个模组的代表版本，但 `m_index` 中同一标识符的各版本是按 CKAN-meta tar 包内文件名**字母序**存放的，从未按版本排序；`versions.first()` 实际是「字母序最小」的版本（Kerbal Konstructs 即 `0.5.1b`）。而官方 CKAN 用版本字典升序后取首个兼容版本，故为 `v1.12.2.0`。启动器内部安装/升级路径用的 `latestOf()`（`RepoIndex::latestFor`，已按版本排序）是正确的，与列表显示不一致。
- **附带后果**：`0.5.1b` 的 `ksp_version` 为 `0.25`（minor < 9），按 `isCompatible` 判定不兼容，默认「显示不兼容」关闭时该模组会被整个隐藏。
- **修复**：`search()` 改为调用 `RepoIndex::latestFor(m_index, it.key())` 按版本取最新，列表显示、兼容性过滤、实际安装三者统一。
- **测试**：新增 `TestRepoIndex` 套件（`latestPicksNewestNotAlphabeticalFirst` 回归用例：0.5.1b / 1.8.1.15 / v1.12.2.0 乱序下必须取到 v1.12.2.0；`latestEmptyIndex` 空索引用例），全部通过。
