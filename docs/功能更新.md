## 2026-10-03 全面代码审查修复：updater 失败流程、下载健壮性与背景缩放性能

**需求**：全面代码审查（上帝类/性能/安全/正确性）后修复 critical+major 问题；GitHub 镜像源风险仅做文档说明。

**启动器改动**（`updater/main.cpp` / `ckan/downloader.cpp` / `mainwindow.{h,cpp}` / `ckanmanager.cpp`）：
- **updater `fatal()` 不终止执行（critical）**：原实现仅调 `QCoreApplication::exit(1)`，但 main() 顺序流程中事件循环未运行，fatal 后代码继续执行——更新包缺失/解压失败时仍会 `clearAppDir()` 清空安装目录、搬运空 stage，最坏导致启动器被清空且新版未就位。改为 `std::exit(1)` 真正终止，并在退出前清除 `.updating` 标记（失败发生在清理前时旧版仍可用，用户手动重开不被更新提示永久挡住）。
- **`Downloader::download()` 无传输超时（major）**：同步下载循环补 `req.setTransferTimeout(kTransferTimeoutMs)`（与 `downloadProgressed` 一致），避免服务器停滞时 QEventLoop 永久挂起。
- **HTTP 状态级错误误续传（major）**：`downloadProgressed()` 原对一切网络错误都把已收字节（含 404/403 错误页 body）append 进 partial 并用 Range 续传，偏移错位。现按 `HttpStatusCodeAttribute` 区分：≥400 直接放弃当前镜像换下一个，仅传输中断（无状态码）才同址续传。
- **窗口拖拽逐帧平滑缩放背景图掉帧（major）**：`resizeEvent` 原每个 resize 事件都做一次 `SmoothTransformation` 全图重缩放。现拖拽期间仅更新几何（label `scaledContents(true)` 即时拉伸旧位图兜底），新增 `m_bgScaleTimer`（单次 150ms）停止缩放后触发一次 `updateBackgroundPixmap()` 精缩消除拉伸模糊。
