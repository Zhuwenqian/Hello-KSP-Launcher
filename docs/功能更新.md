# 功能更新

## 2026-09-12：存档备份目录升级（防重实例名+重存档名冲突）

此前备份目录为 `backups/{实例名}/{存档名}/*.zip`，两个不同实例若同名、且存档同名，备份会相互覆盖。现第 1 级目录附加实例 id 前 8 位（id 为不带花括号的 UUID，前 8 位即首段，如 `550e8400`）：`backups/{实例名-id前8位}/{存档名}/*.zip`。实例 id 全局唯一且重命名实例时不变，因此在任何显式重命名后仍可精确定位，最大限度避免目录冲突。

- **目录计算**（`instancemanager_backup.cpp` `getBackupDirForSave`）：`sanitizeFileName(实例名) + "-" + instanceId.left(8)`；存档名一级保留纯存档名。id 为空时退化为仅使用实例名，保证健壮。
- **惰性迁移**（`migrateLegacyBackups`）：访问存档时把两类旧结构——旧两层 `backups/{实例名}/{存档名}` 与更早单层 `backups/{存档名}`——逐一迁移到新目录；目标已存在（重名冲突）则跳过保持幂等，迁移完的 zip（`*.zip`）搬运后清空旧目录。
- **实例 id 贯穿**：备份相关 `InstanceManager` 接口（`getBackupDirForSave`/`listBackups`/`createBackup`/`restoreBackup`）新增 `instanceId` 参数；`savestabpage`→`instancedetailpage`→`mainwindow`→`savedetailpage` 的 `saveSelected`/`setSavePath` 传递链同步补 id（`savestabpage` 直接用 `m_instance.id`）。
- **备份 zip 文件名格式不变**：`存档名[_备注]_yyyyMMdd_HHmmss.zip`，仅改目录层级。
- **验证**：Qt mingw 编译通过；`ctest` 两套件（test_libckan、test_launcher）全部通过。

## 2026-09-12：自更新系统支持更新器（updater.exe）自更新

更新器受自身保留名单约束（清理/搬运时永远跳过 `updater.exe`），因此无法自我替换。此前 Release 说明要求 v1.2.0 用户手动替换。现改为：当 Release notes 标注"本 Release 含有更新器更新"时，更新完成后**保留更新包 zip**，由重启的新版启动器静默替换 `updater.exe`，无需手动操作。

- **识别提示**（`updatemanager.{h,cpp}` `bodyIndicatesUpdaterUpdate`）：按双语关键短语匹配 Release body（中文"本 Release 含有更新器"或英文"ships an updated built-in updater"），命中即 `ReleaseInfo.updaterUpdate=true`。
- **保留 zip**（`updatemanager.cpp` `applyUpdate`）：Windows 时若 `updaterUpdate`，在 `.updater_update/` 写 `updater_pending` 标记（内容为 zip 文件名）并向 updater 传 `--keep-zip`；updater（`src/updater/main.cpp`）解析 `--keep-zip`，更新完成时不再删除 `.updater_update` 目录。
- **新版启动器替换**（`main.cpp` 启动守卫后、仅 Windows）：`applyPendingUpdaterUpdate` 检测 `updater_pending` → 从保留 zip 内按 basename 查找 `updater.exe`（兼容单一顶层发布目录结构、大小写不敏感）→ 解压到临时文件 → 覆盖应用目录的 `updater.exe` → 成功即整删 `.updater_update`。替换失败弹窗提供「重试 / 忽略」（忽略走 `cleanupPendingUpdaterUpdate` 清理现场），正常情况静默、不打断启动。
- **zip 条目接口**（`updatemanager.{h,cpp}`）：`findZipEntryByBaseName` / `extractZipEntry` 基于 miniz 实现，供查找与解压任意深度 updater 条目。
- **翻译**：新增 7 条 UI 字符串并补 en_US（556 条全译），`.qm` 已重建并同步 `dist/translations`。
- **测试**：`test_launcher` 新增 `updaterUpdateBodyDetection` 与 `zipUpdaterEntry`（中英文提示识别、普通日志不误判、任意深度定位、大小写、不存在的条目、解压内容一致）。`ctest` 两套件全部通过。

## 2026-09-11：修复关闭启动器后进程残留并占用注册表锁

**问题**：进入模组管理、索引正在下载时关闭启动器，窗口关闭但进程不退出，仍在后台继续下载（实测残留进程与 GitHub 有活跃连接）；因 `CKAN/registry.locked` 含存活 PID，重开启动器进模组管理会一直提示被占用并进入 10s 轮询。

- **根因**：退出路径无人取消在途后台任务。`~CKanManager()`（唯一置取消标志并等待 watcher 的地方）是静态析构，与全局线程池 `QThreadPool` 析构的 `waitForDone()`（无限等在途 `QtConcurrent` 任务）顺序不定，实际线程池先等 → 取消标志永不置位 → 索引下载自然运行（镜像×续传重试可拖极久）→ 进程残留、锁不释放。
- **修复（main.cpp）**：连接 `QCoreApplication::aboutToQuit`（QApplication 仍存活时）→ `CKanManager::instance().closeInstance()`：置取消标志 + `cancelInstall()` + `waitForFinished()` 等全部后台任务（下载以 200ms 轮询响应取消）+ 删除当前实例并释放注册表锁。不可依赖静态析构做此清理。
- **修复（modpackcontroller.cpp importFromZip）**：整合包导入任务不受 CKanManager 管理（watcher 挂在控制器上），取消仅靠进度对话框 `wasCanceled`；对话框随窗口销毁后无人取消。现对话框 `destroyed` 信号 → 置 `cancelRequested`（`modpackImportGameData` 周期轮询），后台解压随即中止。
- **异步操作退出安全审计**（其余不改）：模组搜索/反向关系（内存索引遍历，有界 CPU，亚秒）、备份/恢复（槽内 `waitForFinished` 同步等待，退出顺序天然安全）、图标加载（快速有界）、版本检查/更新（主线程 NAM，随 QApplication 析构自动中止）。
- **测试**：`test_launcher` 新增 `TestShutdownCleanup`：后台扫描在途时 `closeInstance()` 不卡死且释放 `registry.locked`、幂等可重复调用、未绑定实例时安全。真机验证：关闭窗口后进程 3s 内干净退出（ExitCode=0）。`ctest` 两套件全部通过。

## 2026-09-11 v1.2.3：KSP 游戏崩溃日志分析

游戏**异常退出**（非用户主动"停止"、非0退出码）时，自动读取 KSP 的 `Player.log` 尾部，检测硬崩溃（Hard Crash）或内存溢出（OutOfMemoryException），有则弹窗给出原因与建议。

- **分析模块**（`playerloganalyzer.{h,cpp}`）：`analyzePlayerLog`（纯字符串解析，供单测）、`analyzePlayerLogFile`（只读文件末尾 512KB，避免日积月累可达数百 MB~GB 的日志全量读取卡顿）、`defaultKspPlayerLogPath`（Windows 固定 `%USERPROFILE%/AppData/LocalLow/Squad/Kerbal Space Program/Player.log`）、`describeSigno`。
  - 判定优先级：先查 `OutOfMemoryException` / `Out of memory` → 无则用正则 `Caught fatal signal[^\r\n]*signo:(\d+)` 匹配原生崩溃段落。
  - signo 全映射中文释义：11=SIGSEGV 段错误、6=SIGABRT 异常终止、4=SIGILL、5=SIGTRAP、7=SIGBUS、8=SIGFPE，未知信号给通用提示。
- **触发与弹窗**（`mainwindow.cpp onGameFinished` / `maybeShowCrashAnalysis`）：异常退出且开启分析时弹 `QMessageBox`，标题区分内存溢出/硬崩溃；正文含信号释义与针对性建议（内存溢出给出减模组、调高内存限制、降纹理质量、关后台应用、换低分辨率星球包贴图等）；提供"打开日志文件"按钮（打开 Player.log 所在文件夹）。日志缺失/未崩溃/平台不支持时静默不打扰。
- **设置项**（`configmanager.{h,cpp}`、`settingspage.{h,cpp}`）：通用组新增「游戏崩溃日志分析」开关（默认开），持久化到 `HKSPL.json` 的 `crashLogAnalysis`；旧配置缺字段兜底为开。
- **测试**：`test_launcher` 新增 `TestPlayerLogAnalyzer`：正常/空日志判 NoCrash、signo:11/6/8 判 HardCrash、OOM 判 OutOfMemory 且优先于信号、文件缺失判 LogMissing、尾部大文件读取命中末尾崩溃、signo 释义含关键中文。`ctest` 两套件全部通过。

## 2026-09-06：模组搜索/筛选提速——行级缓存 + 预解析 + 输入防抖

大索引下模组列表的搜索/筛选/状态判定是主线程卡顿热点：`filterAcceptsRow`/`data()` 每行每次重复执行字符串小写、版本区间解析、已安装状态查询。本轮以「预计算换查询」方式提速，行为与原先逐行实时计算保持一致（含回归测试）。

- **行级预计算缓存**（`modtablemodel.{h,cpp}`）：`ModsTableModel` 新增 `RowCache`（合并小写搜索串 name|identifier|abstract、`compatibleCurrent`、`compatibleRange`、`status`）。`setModules` 一次性 `rebuildStaticCache`，`refreshStatus`（安装/卸载后）与 `setCompatibilityContext`（游戏版本/额外区间变化）只重建对应字段；`statusAt`/数据渲染改用 O(1) 查缓存，去掉了每格 `installedVersion`+版本排序的昂贵重算。
