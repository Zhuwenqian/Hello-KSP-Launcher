# 功能更新

## 2026-09-18 v1.4.0：进入实例管理页的加载提速——存档/飞船/模组数据改为「进入对应 tab 才异步加载」

- **问题**：从首页进入实例管理页时，`InstanceDetailPage::refreshData()` 在主线程同步触发全部二级 tab 的数据装载：模组页立即启动索引加载 + DLL 扫描，存档页同步逐文件解析 `persistent.sfs`、飞船页同步解析全部 `.craft`，多存档/多飞船实例下进入页面明显卡顿，且从未点开的 tab 也白白消耗资源。
- **惰性加载**（`instancedetailpage.cpp` `showSection`）：改为进入对应二级 tab 才触发装载——
  - 模组管理 tab（index 2）→ `setTabActive(true)` 每次进入都触发 `prepareMods()`（索引加载 + DLL 扫描，本就异步）；
  - 存档管理 tab（index 4）→ `loadSaves()`；
  - 飞船管理 tab（index 5）→ `loadShips()`。
  - 进入详情页默认停在「游戏设置」，不再提前做任何重活。
- **模组页**（`modstabpage.{h,cpp}`）：`setInstance` 只记录实例 + 还原列表状态，不再 `prepareMods()`；`setTabActive(true)` 每次进入触发一次装载，保证手动放入/移除的模组 DLL 与索引状态最新。
- **存档页**（`savestabpage.{h,cpp}`）：`setInstanceId` 只记录实例；`loadSaves()` 改为 `QtConcurrent::run` 后台线程遍历目录 + 逐文件解析 `persistent.sfs`，`QFutureWatcher` 就绪后回主线程填充列表（含「正在加载存档...」占位），删除存档后的刷新复用同一异步路径。
- **飞船页**（`shiptabpage.{h,cpp}`）：`setShipsBase` 只记录根目录；`loadShips()` 改为后台线程一次解析 VAB/SPH 两个类型并回主线程填充，行构建抽为 `addShipRow`；删除/导入后的刷新改走 `loadShips()`。
- **线程安全**：`InstanceManager::listSaves/loadSaveInfo/listCraftFiles/loadCraftInfo` 均为纯文件读取（无共享可变状态），后台线程调用安全。
- **验证**：Qt mingw（`E:\Qt\Tools\mingw1310_64`）下 `HelloKSPLauncher` 编译链接通过。
- **测试说明**：UI 异步化改动，不涉及 ckan 库逻辑，未新增自动化测试（与项目内界面层改动惯例一致）。

## 2026-09-18：模组管理新增「列表 / 详情」垂直可拖动分隔条

- **需求**：在模组管理 4 个 tab（元数据/文件/关系/版本）上方、模组列表下方加一条可拖动的分隔条：往下拉则压缩详情四 tab 高度并把 tab 下移，让模组列表变宽（更高）；往上拉则反之。
- **实现**（`modstabpage.cpp` `setupUi`）：引入 `QSplitter(Qt::Vertical)`（对象名 `modSplitter`），上方段 = 列表段（模组表格 + 下载进度条），下方段 = 详情四 tab；初始按 3:2 分配（列表 600 / 详情 400），两侧均禁止折叠（`setChildrenCollapsible(false)`）。底部操作按钮栏固定在分隔条之外，不随拖动缩放。
- **持久化**（`configmanager.{h,cpp}`）：新增 `modSplitterTopHeight()` / `setModSplitterTopHeight(int)`，保存到 `HKSPL.json` 的 `modSplitterTopHeight`（上方列表段高度像素，-1=未设置走默认）。拖动分隔条用 250ms 防抖落盘；全局单份，所有实例共用。
- **还原修正**（`modstabpage.{h,cpp}`）：持久化高度不再于构造期 `setSizes`（页面未布局时 Qt 会按可用空间把 `{savedTop,400}` 重新归一化，详情段被压到最小高、列表段钉死，且归一化触发的 `splitterMoved` 又把该值写回 JSON，导致"一直是 227、拖不动"）。改为首次 `showEvent` 时按分隔条真实高度精确应用 `{savedTop, 剩余空间}`；同时把详情四 tab 最小高从 210 降到 140，给拖动留出实际范围。
- **样式**（`light.qss` / `dark.qss`）：新增 `QSplitter::handle#modSplitter` 规则——6px 圆角手柄，半透明底色，悬停/按下呈主题蓝高亮，明暗主题分别适配。
- **验证**：Qt mingw（`E:\Qt\Tools\mingw1310_64`）下 `HelloKSPLauncher` 编译链接通过。
- **测试说明**：纯布局调整，不涉及业务逻辑，未新增自动化测试。

## 2026-09-18：模组管理列表状态按实例持久化（随改随存）

- **需求**：每个实例的模组管理列表在切换实例或关闭启动器后，重新打开仍停留在原来的查看位置（含滚动位置、底部详情 tab、状态筛选、标签筛选、搜索词、排序、选中模组）。
- **存储**（`configmanager.{h,cpp}`）：新增 `modListViewState(id)` / `setModListViewState(id,obj)`，保存在 `HKSPL.json` **独立配置节** `modListViewState`（键为实例 id）。缺失/旧配置缺字段返回空对象，调用方按默认值兜底（优雅兼容旧配置，不报错）。
- **保存时机**（`modstabpage.cpp`）：随改随存——搜索词/状态筛选/标签筛选/选中行在各自槽内、详情 tab 切换/列头排序/纵向滚动经信号，统一走 300ms 防抖定时器落盘；切换实例（`setInstance`）进入前先同步 flush 上一实例，避免防抖未触发时丢改动。
- **状态内容**：搜索文本、状态筛选（全部/已安装/可升级/未安装）、标签筛选下拉、底部详情 tab 索引、排序列+升降序、纵向滚动值、当前选中模组标识符。反向关系勾选、显示不兼容开关不入（后者已是全局配置）。
- **还原流程**：`setInstance` 时把搜索/状态筛选/详情tab/排序复原到控件；因列表与标签下拉为异步构建，标签选中/选中行/滚动位置在数据就绪（`onModsLoadFinished` → `restoreListStateAfterLoad`）后还原，并用 `m_restorePending` 标志区分"进入实例的首次加载"与"同实例刷新"，避免刷新误重置标签。新实例（无已存状态）不预选、不滚动，仅归一化标签到「全部标签」。
- **验证**：Qt mingw（`E:\Qt\Tools\mingw1310_64`）下 `HelloKSPLauncher` 编译链接通过。
- **测试说明**：ConfigManager 为绑定 `applicationDirPath` 的应用单例，无头单测会覆盖开发者真实 `HKSPL.json`，且还原逻辑依赖异步索引加载，故未新增自动化测试（与项目内实例路径/模态相关功能惯例一致）。

## 2026-09-14：模组安装的推荐/建议改为「逐模组渐进式弹窗」（不再一股脑汇总）

- **收集方式**（`relationshipresolver.{h,cpp}`、`ckan.{h,cpp}`）：新增 `collectOptionalFor(parent, curInstallSet, wantRecommends)`——只收集**单个父模组**自己的推荐(Recommends)/建议(Suggests)候选，跳过已安装/已选/冲突，**不做自动级联**。原先一次性把所有模组的推荐+建议递归级联汇总成一个大列表（`recommendedModules`/`suggestedModules`）的逻辑不再用于弹窗（parseRelationships 保留，`resolve` 的 collects 路径保留供兼容）。
- **安装决策**（`installservice.cpp` `resolveInstallSet`）：改为两阶段渐进式——
  - 阶段一**推荐**：仅对「用户明确安装（勾选/点击）」的模组逐个弹推荐框，勾选结果并入安装集后其新模组入队继续收集（队尾 FIFO，动态循环直至不再新增）；
  - 阶段二**建议**：对当前全部明确模组逐个弹建议框；若新勾选模组的推荐在推荐阶段未展示过则先补弹其推荐，再弹其建议。
  - 同一模组被多次推荐/建议只装一次（按标识符去重）；无候选/已满足的模组静默跳过；每个框标题标注来源父模组。
- **选择弹窗**（`moddecision.{h,cpp}`）：`OptionalModulesHandler` 增加 `parentName` 上下文；`askOptionalModules` 列表顶部新增「全选/全不选」切换按钮（随当前勾选状态动态切换文案）。取消仍中止整次安装。
- **测试**：`test_libckan` 新增 `collectOptionalNoCascade`（逐模组收集、不级联、互不掺入）、`collectOptionalSkipsInstalledAndSelected`（已装/已选跳过）。`test_libckan` 全绿。
- **验证**：Qt mingw 下 `HelloKSPLauncher` 编译链接通过。`test_launcher` 在本机预存在的 Qt 插件缺失崩溃与本次改动无关（`TestInstallService` 隔离运行通过）。

## 2026-09-12：修复自绘标题栏窗口四边无法拉伸&#x20; + 最小化无动画

- **拉伸根因**：`Qt::FramelessWindowHint` 会把底层样式里的 `WS_THICKFRAME`（可缩放）剥掉，导致 `WM_NCHITTEST` 返回边框码也无法进入缩放循环（四边完全拉不动）。
- **拉伸补丁**（`mainwindow.{h,cpp}` `applyNativeFrameStyle`，仅 Windows）：保留 `FramelessWindowHint` 外观，首次 `showEvent` 及 `toggleMaximize` 后用 `SetWindowLongPtr(GWL_STYLE)` 补回 `WS_THICKFRAME | WS_MINIMIZEBOX | WS_MAXIMIZEBOX`，并 `SetWindowPos(SWP_FRAMECHANGED)`；`WM_NCHITTEST` 边缘抓取区加宽到 8px。刻意不补 `WS_CAPTION`，故不绘制系统标题栏。
- **最小化动效**：`WS_POPUP` 纯无边框窗口无法获得 DWM 原生最小化动画（原生动画只对带 `WS_CAPTION` 的标准窗口播放），故采用自绘动效（`onWindowMinClicked`，仅 Windows）：先 `showMinimized()` 真正最小化，再抓取当前窗口快照作为 `Tool+置顶+半透明` 的 ghost 悬浮层，向任务栏方向缩小+淡出（`QPropertyAnimation` geometry/opacity，280ms `InCubic`），结束 `deleteLater`。
- **效果**：四边自由平滑拉伸；最小化为"缩小淡出飞入任务栏"的自带动效（非系统原生，但不再瞬间消失）。

## 2026-09-11：修复关闭启动器后进程残留并占用注册表锁

**问题**：进入模组管理、索引正在下载时关闭启动器，窗口关闭但进程不退出，仍在后台继续下载（实测残留进程与 GitHub 有活跃连接）；因 `CKAN/registry.locked` 含存活 PID，重开启动器进模组管理会一直提示被占用并进入 10s 轮询。

- **根因**：退出路径无人取消在途后台任务。`~CKanManager()`（唯一置取消标志并等待 watcher 的地方）是静态析构，与全局线程池 `QThreadPool` 析构的 `waitForDone()`（无限等在途 `QtConcurrent` 任务）顺序不定，实际线程池先等 → 取消标志永不置位 → 索引下载自然运行（镜像×续传重试可拖极久）→ 进程残留、锁不释放。
- **修复（main.cpp）**：连接 `QCoreApplication::aboutToQuit`（QApplication 仍存活时）→ `CKanManager::instance().closeInstance()`：置取消标志 + `cancelInstall()` + `waitForFinished()` 等全部后台任务（下载以 200ms 轮询响应取消）+ 删除当前实例并释放注册表锁。不可依赖静态析构做此清理。
- **修复（modpackcontroller.cpp importFromZip）**：整合包导入任务不受 CKanManager 管理（watcher 挂在控制器上），取消仅靠进度对话框 `wasCanceled`；对话框随窗口销毁后无人取消。现对话框 `destroyed` 信号 → 置 `cancelRequested`（`modpackImportGameData` 周期轮询），后台解压随即中止。
- **异步操作退出安全审计**（其余不改）：模组搜索/反向关系（内存索引遍历，有界 CPU，亚秒）、备份/恢复（槽内 `waitForFinished` 同步等待，退出顺序天然安全）、图标加载（快速有界）、版本检查/更新（主线程 NAM，随 QApplication 析构自动中止）。
- **测试**：`test_launcher` 新增 `TestShutdownCleanup`：后台扫描在途时 `closeInstance()` 不卡死且释放 `registry.locked`、幂等可重复调用、未绑定实例时安全。真机验证：关闭窗口后进程 3s 内干净退出（ExitCode=0）。`ctest` 两套件全部通过。
